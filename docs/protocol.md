# Backend ↔ Core protocol

Defined in [`api/proto/threavia/backend/v1`](../api/proto/threavia/backend/v1),
following specification sections 9 and 26. The Go bindings in `gen/` are
generated by `make generate` and are never edited by hand.

## Shape

One service, one bidirectional stream:

```proto
service BackendControl {
  rpc Connect(stream BackendToCore) returns (stream CoreToBackend);
}
```

Everything else is a `oneof` branch of those two envelopes. There are no
provider-specific RPCs, and no provider assumption in any message.

| Backend → Core | Core → Backend |
| --- | --- |
| `Hello` | `Welcome` |
| `Heartbeat` | `StartJob` |
| `StatusUpdate` | `CancelJob` |
| `ReconcileState` | `ValidationResolution` |
| `JobEvent` | `UserInputResolution` |
| `EphemeralJobEvent` | `JobInputNow` |
| `CommandResult` | `JobInputNext` |
| `CoreToolRequest` | `ReconcileInstruction` |
| | `EventAck` |
| | `CoreToolResponse` |

## Connection

The backend always dials Core; Core never needs inbound connectivity to a
laptop. The connection carries the backend credential as gRPC metadata:

```text
authorization: Bearer <backend credential>
```

Core resolves it to a BackendInstance before reading anything from the stream.
The credential is never logged, and provider credentials never travel on this
stream at all.

## Handshake

1. The backend sends `Hello` as the first message: protocol version, SDK,
   backend identity, instance name, capabilities, optional feature flags and
   capacity.
2. Core rejects a protocol version it does not speak with `FailedPrecondition`:
   the protocol version is the contractual compatibility boundary.
3. Core answers `Welcome` with a fresh `connection_id`, the resolved
   BackendInstance id and the heartbeat interval it expects.
4. The backend reports its `ReconcileState`, then replays any event Core has not
   acknowledged, then starts heartbeating.

A `Hello` sent again mid-stream is rejected with `InvalidArgument`.

## Connection lease

Only one connection is active per BackendInstance. A newly authenticated
connection receives a new `connection_id` and supersedes the previous one, which
is closed with `Aborted` and receives no further work.

On shutdown Core closes every connection with `Unavailable`; backends reconnect
with exponential backoff.

## Event identity

Three identifiers, each with one job:

| Identifier | Scope | Purpose |
| --- | --- | --- |
| `backend_event_id` | unique per BackendInstance | deduplication of at-least-once delivery |
| `backend_sequence` | monotonic per Job | ordering and replay-gap detection |
| global sequence | Core-wide | client cursor, assigned by Core on persistence |

A per-Job sequence is what lets unrelated concurrent Jobs stream without being
serialised against each other.

Core acknowledges persisted events with `EventAck` carrying
`through_backend_sequence`; only then may a backend drop them from its durable
buffer. Until the Core event pipeline is implemented, Core sends no
acknowledgement, so nothing is dropped.

`EphemeralJobEvent` is the exception: progress and "agent working" signals are
streamed for liveness and never persisted.

## Commands and results

A `CoreToBackend` message carrying a `command_id` expects a `CommandResult` with
the same id. A backend that cannot honour a command answers
`accepted: false` with an error code rather than silently ignoring it.

`ReconcileInstruction` carries the Core decision after a reconnection: replay
events from a sequence, reissue a cancellation, or abandon a Job. The rule is
the one of section 9: Core is the source of truth for desired logical state, the
backend is the source of truth for what actually happened locally.

## Core Tools

An agent tool call travels as `CoreToolRequest` and is answered by
`CoreToolResponse`, correlated by `request_id`. The tools available for a Job are
described in the `ProjectContext` of `StartJob`, so a backend never hardcodes a
tool name.

## Compatibility

`ProtocolVersion` is declared in `common.proto` and is the single source of truth
for both sides. Protobuf compatibility is preserved: fields are added, never
renumbered or repurposed. `make proto-breaking` checks this against the default branch.
